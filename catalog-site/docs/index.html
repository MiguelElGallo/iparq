iParq CLI and Agent Skill documentation

iParq inspects Parquet and Vortex storage metadata locally. It does not upload inspected files, expose a hosted API, or modify input data. Python 3.10 or later is required.

Current release: iParq 0.9.0. See the release notes for the changes.

Quick start

uvx --refresh iparq inspect FILE.parquet --format json --details --sizes

For Vortex, use Python 3.11 or newer with the optional reader.

uvx --from 'iparq[vortex]' iparq inspect FILE.vortex --format json

For a persistent installation, run pip install iparq for Parquet or pip install 'iparq[vortex]' for both formats. The default output uses Rich tables. Use --format json for scripts and agents.

Inspection options

  • --metadata-only reports the file summary. For Parquet this includes the creator, row groups, version, and serialized metadata size. For Vortex it includes the version, row and field counts, root type, and nullability.
  • --column NAME restricts column-level output.
  • In Rich output, --details adds Parquet storage details or Vortex scan split ranges. Vortex ranges include the start row and exclude the stop row.
  • In Rich output, --sizes adds Parquet column sizes and compression ratios, or Vortex file and postscript sizes in bytes. Vortex JSON always includes both sizes in metadata.

Machine-readable contract

A single input emits one JSON object. Multiple inputs emit one JSON array whose entries include the file path. Diagnostics are written to stderr. If any input is unreadable, the process exits non-zero while keeping successful JSON output valid.

Agent use

The iParq Parquet and Vortex Inspector Skill explains when to invoke the CLI, how to select the minimum useful detail, and how to distinguish observed metadata from recommendations. The ARD catalog publishes representative queries and the canonical Skill URL.

Safety boundary

iParq is read-only and local. It inspects file metadata without querying row data. Treat index and Bloom-filter fields as evidence that structures exist, not as proof that a downstream engine will use them. Preserve exact codec, encoding, physical-type, logical-type, and creator names when reporting results.
